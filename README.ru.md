# EVE Builders для Alliance Auth

[English version](README.md)

Корпоративные заказы на производство для [Alliance Auth](https://gitlab.com/allianceauth/allianceauth)
(AA). Менеджер публикует заказ («20 Punisher по 1,5 млн, срок до пятницы»), строитель
берёт часть заказа, производит и сдаёт обычным игровым контрактом «обмен предметами»
на корпорацию. Плагин сам читает контракты корпорации, сверяет их с заказом и
засчитывает строителю результат, когда контракт принят. Обо всех событиях сообщает
Discord.

Плагин — переписанное под Alliance Auth Java-приложение
[eve-builders](https://github.com/AntonAzarenko/eve-builders) автора AntonAzarenko.
Его код не копировался, идея и процесс его. Спасибо!

> [!IMPORTANT]
>
> **Нужен Alliance Auth v5**, работающий воркер Celery **и Celery beat** (контракты
> проверяет задача по расписанию).

## Возможности

- **Заказы**: предмет из каталога EVE, количество, цена за единицу, приоритет, срок
  сдачи, уровень доступа, место доставки, примечание. Номер заказа выглядит как
  `N20261101-1` (дата и номер за день).
- **Строители** берут любую часть заказа и могут вернуть её, пока не прошла половина
  времени между созданием заказа и сроком сдачи. Позже вернуть может только менеджер.
- **Уровни доступа** Base, Middle, Senior: строитель не видит заказы выше своего уровня.
- **Сдача контрактами**: строитель создаёт контракт «обмен предметами» на корпорацию с
  номером заказа в названии. Плагин засчитывает его, когда контракт принят в игре.
  Никакого ручного учёта.
- Страница **«Мои заказы»**: что взято, что ждёт принятия, что готово, цены и сроки, а
  также контракты, которые не удалось засчитать, и почему.
- **Инструменты менеджера**: страница заказа с историей, изменение, удаление
  (отмена), освобождение части, ручной зачёт (в том числе контракта без номера
  заказа), уровни строителей, места доставки и страница «Управление» со списком того,
  что требует внимания.
- **Уведомления в Discord** через вебхуки.
- Интерфейс на английском и русском.
- **Удобства**: поиск и фильтры над списком заказов, иконки предметов, кнопки копирования
  номера заказа и цены, даты в часовом поясе вашего браузера.

## Как это работает

1. Менеджер создаёт заказ. В Discord приходит сообщение.
1. Строитель открывает **Corporate orders** (Корпоративные заказы) и берёт часть.
1. Строитель производит предметы и создаёт **контракт «обмен предметами» на
   корпорацию** (см. [Правила контракта](#%D0%BF%D1%80%D0%B0%D0%B2%D0%B8%D0%BB%D0%B0-%D0%BA%D0%BE%D0%BD%D1%82%D1%80%D0%B0%D0%BA%D1%82%D0%B0)): в названии номер заказа,
   цена равна цене за единицу, умноженной на количество.
1. В течение нескольких минут плагин видит контракт, а часть в заказе получает статус
   **Under review**.
1. Когда контракт принят в игре, плагин засчитывает предметы, показывает, кто его
   принял, и сообщает в Discord. Когда всё засчитано, заказ получает статус **Done**.

## Установка

### Требования

- Alliance Auth 5 (проверено на 5.4), Python 3.10 или новее
- [django-eveuniverse](https://pypi.org/project/django-eveuniverse/) 2.2 или новее
  (каталог предметов). Если он уже есть в вашем Auth, ничего делать не нужно.
- Работающие воркер Celery и **Celery beat**

### Установка пакета

Пакета в PyPI нет: ставим колесо со страницы релиза. Сначала активируйте виртуальное
окружение вашего Auth.

```shell
pip install https://github.com/baphomet448/aa-eve-builders/releases/download/v0.2.1/aa_eve_builders-0.2.1-py3-none-any.whl
```

В `local.py` добавьте приложения в `INSTALLED_APPS` (`eveuniverse` только если его там
ещё нет):

```python
INSTALLED_APPS += [
    "eveuniverse",
    "evebuilders",
]
```

Выполните миграции и перезапустите Auth:

```shell
python manage.py migrate
python manage.py collectstatic --noinput
```

И перезапустите сервисы (например, `supervisorctl restart myauth:` на стандартной
установке).

#### Docker (allianceauth-docker)

В образе Auth нет `git`, поэтому тоже ставим колесо. Добавьте строку в
`conf/requirements.txt`:

```text
aa-eve-builders @ https://github.com/baphomet448/aa-eve-builders/releases/download/v0.2.1/aa_eve_builders-0.2.1-py3-none-any.whl
```

Строки `INSTALLED_APPS` и задачи по расписанию добавьте в `conf/local.py`. Затем пересоберите
образ и **пересоздайте** контейнеры (`docker compose restart` недостаточно: он не меняет
образ и не перечитывает `.env`), и выполните миграции в контейнере:

```shell
docker compose build
docker compose --env-file=.env up -d --force-recreate
docker compose exec allianceauth_gunicorn bash
auth migrate
auth collectstatic --noinput
```

### Задачи по расписанию

Добавьте две задачи в `CELERYBEAT_SCHEDULE` в `local.py` и перезапустите Celery beat:

```python
CELERYBEAT_SCHEDULE["evebuilders_sync_catalog"] = {
    "task": "evebuilders.tasks.sync_catalog",
    "schedule": crontab(minute="30", hour="4"),
}

CELERYBEAT_SCHEDULE["evebuilders_sync_contracts"] = {
    "task": "evebuilders.tasks.sync_contracts",
    "schedule": crontab(minute="*"),
}
```

- `sync_catalog` раз в сутки обновляет каталог предметов (здесь в 04:30 UTC).
- `sync_contracts` запускается **каждую минуту**, но обращается к ESI только когда у ESI
  есть свежие данные (список контрактов ESI кеширует примерно на пять минут) и не чаще
  минимального интервала. Большинство запусков ничего не делают и возвращают
  `not_yet`: это нормально.

### Скоуп ESI

Плагин читает контракты корпорации токеном **одного участника корпорации**, роль в
игре не нужна. В CCP-приложении вашего Auth (<https://developers.eveonline.com/>)
должен быть включён скоуп:

```text
esi-contracts.read_corporation_contracts.v1
```

Если его там нет, добавьте его в приложение.

### Права

Выдайте эти права в админке Auth группам или состояниям (state). Они называются
«EVE Builders ... | general | ...»:

| Право                        | Кому       | Что разрешает                            |
| ---------------------------- | ---------- | ---------------------------------------- |
| `evebuilders.builder_access` | строителям | Смотреть и брать корпоративные заказы    |
| `evebuilders.manage_access`  | менеджерам | Управлять заказами и настройками плагина |

Пункты меню («Corporate orders» и «My orders») видят только люди с одним из этих прав.
Если вы группируете меню в папки (админка Auth, Menu), положите их в удобную папку.

### Первая настройка в веб-интерфейсе

Менеджер делает это один раз (кнопка **Settings** плагина):

1. **ESI and catalog, ESI connection**: нажмите **Connect** персонажем, который состоит в
   корпорации. Этим токеном читаются контракты корпорации.
1. **ESI and catalog, Item catalog**: нажмите **Update catalog** и подождите несколько
   минут, пока загрузятся предметы (дальше он обновляется сам раз в сутки).
1. **Builder levels**: задайте уровни строителей (по умолчанию Base).
1. **Stations**: добавьте места доставки (найдите систему по части названия, выберите
   станцию либо добавьте систему с названием структуры). Пока список пуст, место
   доставки в заказе вписывается текстом.

Затем попробуйте кнопку **Create order**.

## Настройки

Все настройки необязательны. Задаются в `local.py`.

| Настройка                                   | По умолчанию                           | Значение                                                               |
| ------------------------------------------- | -------------------------------------- | ---------------------------------------------------------------------- |
| `EVEBUILDERS_CATALOG_CATEGORY_IDS`          | `[4, 6, 7, 8, 18, 22, 32, 65, 66, 87]` | Категории EVE в каталоге предметов                                     |
| `EVEBUILDERS_CATALOG_GROUP_IDS`             | `[]`                                   | Отдельные группы сверх категорий (например `1136`, Fuel Block)         |
| `EVEBUILDERS_CATALOG_MIN_INTERVAL_MINUTES`  | `15`                                   | Минимальный интервал между обновлениями каталога                       |
| `EVEBUILDERS_SYNC_MIN_INTERVAL_SECONDS`     | `60`                                   | Минимальный интервал между проверками контрактов (кнопка и расписание) |
| `EVEBUILDERS_DISCORD_NEW_ORDER_WEBHOOK_URL` | пусто                                  | Вебхук для новых, изменённых и удалённых заказов                       |
| `EVEBUILDERS_DISCORD_NEW_ORDER_THREAD_ID`   | пусто                                  | ID треда этого канала, если вебхук пишет в тред                        |
| `EVEBUILDERS_DISCORD_COMPLETE_WEBHOOK_URL`  | пусто                                  | Вебхук для отчётов о контрактах и сдаче                                |
| `EVEBUILDERS_DISCORD_COMPLETE_THREAD_ID`    | пусто                                  | ID треда этого канала                                                  |
| `EVEBUILDERS_DISCORD_NOTIFY_TAKEN`          | `True`                                 | Сообщать, что строитель взял часть заказа                              |

## Уведомления в Discord

Создайте вебхук в каждом канале Discord (настройки канала, Интеграции). Затем передайте
плагину два адреса в админке Django: **EVE BUILDERS, Discord settings**. Изменение
действует сразу, перезапуск не нужен. Адрес вебхука секретный (кто его знает, может
писать в канал), поэтому он правится в админке, а не на страницах плагина.

Пустой канал в админке берёт значение из `local.py` (`EVEBUILDERS_DISCORD_*`, см.
«Настройки»), так что старая настройка продолжает работать. В Docker то, что лежит в
`.env`, доходит до воркера только после пересоздания контейнеров.

ID ветки необязателен. Он нужен, только если вебхук должен писать в ветку (для
форум-канала он обязателен). Включите в Discord режим разработчика и скопируйте ID
ветки. Вебхук создавайте в родительском канале этой ветки.

Сообщения отправляются в фоне, при занятости Discord делается несколько повторов. Тексты
на русском, и каждое сообщение начинается с эмодзи, показывающего вид события. Проверить
каналы можно командой ниже (она отправляет тестовое сообщение с @everyone):

```shell
python manage.py evebuilders_test_notification
```

| Канал        | Что приходит                                                                                                                                                      |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Новые заказы | заказ создан, изменён или удалён                                                                                                                                  |
| Отчёты       | строитель взял часть, вернул её, менеджер освободил; контракт ждёт принятия, принят и зачтён или не может быть засчитан (с причиной); ESI-токен перестал работать |

## Правила контракта

Контракт засчитывается, когда выполняется **всё** перечисленное:

- это контракт **«обмен предметами» на корпорацию** (не на человека);
- в названии есть **номер заказа**, например `N20261101-1` (другой текст рядом
  допускается; два разных номера не принимаются);
- его создал персонаж с аккаунта Auth строителя, который **взял** этот заказ;
- в него **входит** предмет заказа (другие предметы в этом же контракте
  игнорируются);
- **цена** равна цене за единицу, умноженной на количество этого предмета (допуск
  0,01 ISK);
- количество не больше того, что строителю ещё осталось сдать.

Подходящий контракт имеет статус **Under review**, пока его не примут, затем
**засчитывается**. Контракт, который не подошёл, показывается строителю в блоке
«Contracts that could not be counted» с причиной, а менеджерам на странице «Управление»;
менеджер может зачесть его вручную, посмотрев сам контракт. Удалённый или
просроченный контракт пропадает из списка сам.

> [!NOTE]
>
> ESI кеширует список контрактов корпорации примерно на пять минут. Новый или только
> что принятый контракт появится после обновления ответа ESI. Страница «Мои заказы»
> показывает, когда ожидается следующая автоматическая проверка.

## Команды управления

```shell
python manage.py evebuilders_sync_catalog        # обновить каталог предметов сейчас
python manage.py evebuilders_sync_contracts      # прочитать и применить контракты сейчас
python manage.py evebuilders_show_contracts      # показать контракты корпорации так, как их отдаёт ESI
python manage.py evebuilders_load_systems        # (пере)загрузить названия солнечных систем
python manage.py evebuilders_test_notification   # отправить тестовое сообщение в Discord
```

У каждой команды есть `--help`. Названия систем (для поиска системы по части названия)
загружаются сами при первом поиске.

## Обновление

```shell
pip install -U https://github.com/baphomet448/aa-eve-builders/releases/download/<версия>/aa_eve_builders-<версия>-py3-none-any.whl
python manage.py migrate
python manage.py collectstatic --noinput
```

После этого перезапустите сервисы. Если обновление меняет пункты меню, страницы Auth могут
показывать ошибку, пока не выполнена `python manage.py migrate`: выполните её и
перезагрузите страницу.

В Docker поменяйте версию в строке `conf/requirements.txt` (тег и имя файла), затем
выполните `docker compose build`, `docker compose --env-file=.env up -d --force-recreate`,
а в контейнере `auth migrate` и `auth collectstatic --noinput`.

## Известные ограничения

- Одна корпорация и один ESI-токен. Заказы корпоративные; личные заказы в планах.
- Публичный ESI знает только NPC-станции. Для структур игроков (и червоточин)
  менеджер добавляет систему и вписывает название структуры.
- Сообщения в Discord только на русском.
- Даты и сроки считаются в UTC.
- Названия статусов, приоритетов и уровней доступа (Done, High, Senior ...)
  намеренно оставлены английскими.
